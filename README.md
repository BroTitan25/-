# Эмулятор языка оболочки ОС — Вариант №1

Эмулятор командной строки, имитирующий работу в UNIX-подобной ОС.
Реализован в форме графического интерфейса (GUI) на Python/Tkinter.

## 1. Общее описание

Проект выполняется поэтапно (см. историю коммитов):

1. **REPL** — минимальный прототип с заглушками команд `ls`, `cd`, `exit`. ✅
2. **Конфигурация** — параметры командной строки (путь к VFS, путь к
   стартовому скрипту), отладочный вывод параметров при запуске. ✅
3. **VFS** — виртуальная файловая система, загружаемая из CSV-файла,
   все операции — только в памяти. ✅
4. **Основные команды** — реальная логика `ls`/`cd`, добавлены `date`,
   `pwd`, `history`. ✅
5. **Дополнительные команды** — `cp`, `vfs-load <путь>`. ✅

## 2. Функции и настройки

| Команда     | Описание                                                        |
|-------------|-------------------------------------------------------------------|
| `ls [путь]` | Список содержимого директории VFS (по умолчанию — текущая).       |
| `cd <путь>` | Смена текущей директории VFS. Поддерживает `.`, `..`, абсолютные и относительные пути. |
| `exit`      | Завершение работы эмулятора.                                      |
| `pwd`       | Вывод текущего пути в VFS.                                        |
| `date`      | Вывод текущей даты и времени реальной ОС.                         |
| `history`   | Вывод истории введённых команд.                                   |
| `cp <src> <dst>` | Копирование файла/директории внутри VFS (только в памяти).   |
| `vfs-load <путь>` | Загрузка новой VFS с диска, замена текущей.                |

Параметры командной строки:

- `--vfs <путь>` — путь к CSV-файлу физического расположения VFS.
- `--script <путь>` — путь к стартовому скрипту (список команд эмулятора,
  выполняемых последовательно при запуске; ошибочные строки пропускаются,
  на экране имитируется диалог ввода/вывода).

При старте эмулятор выводит в консоль отладочный дамп всех заданных
параметров.

### Формат VFS (CSV)

```csv
path,type,content
/docs,dir,
/docs/readme.txt,file,SGVsbG8sINGN0L
/docs/sub,dir,
/docs/sub/data.bin,file,QmluYXJ5IGRhdGE=
```

- `path` — абсолютный путь элемента внутри VFS.
- `type` — `dir` или `file`.
- `content` — для файлов: данные в base64 (для двоичных данных — тоже
  base64); для директорий поле пустое.

## 3. Сборка и запуск

Зависимости: Python 3.9+ (используется только стандартная библиотека,
включая `tkinter`).

```sh
# Запуск GUI
./run.sh --vfs vfs_samples/minimal.csv --script startup_scripts/stage5_demo.txt

# То же самое через Makefile
make run ARGS="--vfs vfs_samples/minimal.csv"

# Запуск тестов
make test
```

## 4. Примеры использования

Интерактивный ввод в открывшемся окне эмулятора:

```
user@host:/$ pwd
/
user@host:/$ ls
docs
user@host:/$ cd docs
user@host:/docs$ ls
readme.txt
sub
user@host:/docs$ cp readme.txt readme_copy.txt
user@host:/docs$ vfs-load vfs_samples/deep_nested.csv
VFS перезагружена из: vfs_samples/deep_nested.csv
user@host:/$ history
1  pwd
2  ls
3  cd docs
4  ls
5  cp readme.txt readme_copy.txt
6  vfs-load vfs_samples/deep_nested.csv
7  history
user@host:/$ exit
```

Обработка ошибок:

```
user@host:/$ cd not_existing_dir
ошибка: cd: путь не найден: not_existing_dir
user@host:/$ foobar
ошибка: неизвестная команда 'foobar'
user@host:/$ vfs-load /no/such/file.csv
ошибка: файл VFS не найден: /no/such/file.csv
```

## 5. Структура репозитория

```
.
├── README.md
├── .gitignore
├── Makefile
├── run.sh
├── src/                 # исходный код (package src)
│   ├── main.py          # GUI и точка входа
│   ├── emulator.py      # состояние сессии и диспетчеризация команд
│   ├── vfs.py            # виртуальная файловая система
│   ├── parser.py         # разбор командной строки
│   ├── commands.py       # общие исключения
│   └── config.py         # разбор CLI-параметров, отладочный дамп
├── tests/                # unit-тесты (unittest)
├── vfs_samples/           # примеры VFS (CSV)
├── startup_scripts/       # стартовые скрипты эмулятора (по этапам)
└── scripts/                # скрипты реальной ОС для тестирования
```

## 6. Известные ограничения

- `date` показывает время реальной ОС (не является частью VFS).
- `vfs-load` принимает путь на диске реальной ОС (а не внутри VFS) —
  так как загружает новую VFS «с нуля», согласно заданию Варианта №1.
- Формат VFS — CSV с колонками `path,type,content`; двоичные данные
  кодируются в base64 (см. раздел «Формат VFS» выше).
